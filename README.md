# Simple Payment System

Учебная симуляция платёжной системы на Go. Проект демонстрирует единый модуль
для работы с разными способами оплаты, хранение информации об операциях и их
отмену.

> **Статус:** WIP. Это демонстрационный проект: реальные платёжные сервисы не
> подключены, данные хранятся только в памяти процесса, а идентификаторы
> генерируются псевдослучайно.

## Возможности

- создание платежа с описанием, суммой и способом оплаты;
- генерация идентификатора операции;
- получение информации о платеже или списка всех платежей;
- отмена ранее созданной операции;
- единый интерфейс `PaymentMethod` для способов оплаты;
- HTTP API на стандартной библиотеке Go;
- демонстрационный веб-интерфейс с тестовым терминалом;
- выбор способа оплаты в веб-интерфейсе: карта, СБП или электронный кошелёк.

## Способы оплаты

В каталоге `payments/methods` доступны симуляции следующих способов оплаты:

- банковская карта — `methods.NewBank()`;
- СБП — `methods.NewSBP()`;
- электронный кошелёк — `methods.NewWallet()`;
- PayPal — `methods.NewPayPal()`;
- криптовалюта — `methods.NewCrypto()`;
- бонусы — `methods.NewBonus()`.

HTTP API принимает способы оплаты, поддержанные функцией `selectedPaymentMethod`
в `main.go`: `Карта`, `СБП` и `Кошелёк`. Остальные реализации доступны для
использования напрямую из Go-кода.

Каждый метод реализует интерфейс `PaymentMethod`. При проведении и отмене
операции он выводит сообщение в консоль. Реального списания средств и
интеграции с платёжными провайдерами нет.

## Требования

- Go **1.27.1** или совместимая версия;
- браузер для работы с веб-интерфейсом.

Проект использует только стандартную библиотеку Go и не требует загрузки
сторонних зависимостей.

## Быстрый старт

```bash
git clone https://github.com/arccthecoder/Simple-payment-system.git
cd Simple-payment-system
go run .
```

После запуска сервер будет доступен по адресу
[`http://localhost:8080`](http://localhost:8080). Статические файлы веб-
интерфейса раздаются из каталога `index`.

Для остановки сервера нажмите `Ctrl+C`.

## HTTP API

Сервер предоставляет API на следующих маршрутах:

| Метод | Маршрут | Назначение |
| --- | --- | --- |
| `POST` | `/api/payments` | создать платёж |
| `GET` | `/api/payments` | получить все платежи |
| `GET` | `/api/payments/{id}` | получить платёж по ID |
| `DELETE` | `/api/payments/{id}` | отменить платёж |

### Создать платёж

```http
POST /api/payments
Content-Type: application/json
```

Тело запроса:

```json
{
  "description": "Покупка товара",
  "usd": 100,
  "method": "Карта"
}
```

Поля `description` и `method` должны быть непустыми, а `usd` — положительным
целым числом. Допустимые значения `method` для HTTP API: `Карта`, `СБП` и
`Кошелёк`.

Пример через `curl`:

```bash
curl -X POST http://localhost:8080/api/payments \
  -H "Content-Type: application/json" \
  -d '{"description":"Покупка товара","usd":100,"method":"Карта"}'
```

Успешный ответ содержит сгенерированный ID:

```json
{
  "id": 123456789
}
```

ID будет отличаться при каждом запуске и создании операции.

### Получить все платежи

```http
GET /api/payments
```

```bash
curl http://localhost:8080/api/payments
```

Ответ — объект, в котором ключами являются ID операций:

```json
{
  "123456789": {
    "Description": "Покупка товара",
    "Usd": 100,
    "Cancelled": false
  }
}
```

### Получить платёж по ID

```http
GET /api/payments/{id}
```

```bash
curl http://localhost:8080/api/payments/123456789
```

Ответ содержит описание, сумму и признак отмены:

```json
{
  "Description": "Покупка товара",
  "Usd": 100,
  "Cancelled": false
}
```

### Отменить платёж

```http
DELETE /api/payments/{id}
```

```bash
curl -X DELETE http://localhost:8080/api/payments/123456789
```

Ответ:

```json
{
  "status": "cancelled"
}
```

Некорректный JSON, неположительная сумма, пустые обязательные поля и
неподдерживаемый способ оплаты возвращают `400 Bad Request`. Для неподдержанных
HTTP-методов сервер возвращает `405 Method Not Allowed`.

> Платежи хранятся в памяти процесса. После перезапуска приложения список
> операций очищается.

## Пример использования в Go

```go
package main

import (
    payment "payment/payments"
    "payment/payments/methods"
)

func main() {
    paymentModule := payment.NewPaymentModule(methods.NewBank())

    paymentID := paymentModule.Pay("Покупка товара", 100)
    info := paymentModule.Info(paymentID)
    allPayments := paymentModule.AllInfo()

    paymentModule.Cancel(paymentID)

    _, _ = info, allPayments
}
```

Для выбора способа оплаты для конкретной операции можно использовать
`PayWithMethod`:

```go
paymentID := paymentModule.PayWithMethod(
    methods.NewSBP(),
    "Покупка товара",
    100,
)
```

## Архитектура

Платёжный модуль отделён от конкретного способа оплаты через интерфейс:

```go
type PaymentMethod interface {
    Pay(usd int) int
    Cancel(id int)
}
```

`PaymentModule` отвечает за:

- вызов выбранного способа оплаты;
- сохранение информации о платеже и метода, которым он был создан;
- поиск операции по ID;
- отмену операции через исходный способ оплаты;
- выдачу копии списка платежей.

HTTP-сервер в `main.go` дополнительно валидирует входные данные, выбирает
реализацию по полю `method` и раздаёт статические файлы из `index`.

## Добавление нового способа оплаты

1. Создайте новый тип в `payments/methods`.
2. Реализуйте методы `Pay` и `Cancel`.
3. Если способ должен быть доступен через HTTP API, добавьте его в
   `selectedPaymentMethod` в `main.go`.
4. Передайте новый тип в `payment.NewPaymentModule` или
   `PaymentModule.PayWithMethod`.

Пример:

```go
type Wallet struct{}

func (Wallet) Pay(usd int) int {
    // Логика симуляции оплаты.
    return 1
}

func (Wallet) Cancel(id int) {
    // Логика симуляции отмены.
}
```
